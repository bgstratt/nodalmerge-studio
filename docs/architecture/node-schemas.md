# Studio node schemas (v1)

Companion to the [v1 architecture specification](./v1-architecture-spec.md) (AP-1 persistence rules).

All authoritative Studio entities are stored as immutable NodalMerge nodes.

## Schema path convention

Use versioned kind paths:

| Entity | Kind path |
|--------|-----------|
| Work unit | `studio/work-unit/v1` |
| Task | `studio/task/v1` |
| Merge proposal | `studio/merge-proposal/v1` |
| Known good state | `studio/known-good-state/v1` |

Constants live in `NodalMerge.Studio.Storage.StudioNodeKind`.

## Rules

1. **Authoritative entities** — `WorkUnit`, `Task`, `MergeProposal`, and `KnownGoodState` serialize to nodes on agent/work branches.
2. **Derived state** — `ExecutionSnapshot` is not persisted as authoritative storage. It is generated by Projection Manager / Agent Runtime and invalidated on projection refresh.
3. **Task intent** — Tasks MUST NOT contain DAG node references. Tasks represent intent, not storage topology.
4. **Branch operations** — `branch.create`, `branch.checkout`, and promotion delegate to NodalMerge topology APIs via Storage.
5. **Human merge gate** — Merge service never bypasses human approval for promotion in v1.

## Payload format (scaffold)

Node payloads are JSON documents. Schema versioning is encoded in the kind path (`/v1`). Future schema changes add `studio/{entity}/v2` rather than mutating existing nodes.

Implementation of read/write against live NodalMerge branches is deferred to Slice 1.
