# Tree object format (frozen contract)

Status: **v1 + v2 frozen 2026-07-15** (slice S1.0 of `plans/cas-distribution-and-storage.md`,
Phase 1). This format is frozen the moment one peer writes one tree blob — treat any change
to the byte encoding as a format break requiring a `version` bump. Golden vectors:
`tests/NodalMerge.Studio.Integration.Tests/TestData/tree-format-vectors.v1.json`.

## What a tree object is

A tree object is an ordinary CAS blob that encodes a repository snapshot's `path → file
blob hash` map (or one directory of it, in v2). Its identity is the **BLAKE3 hash of its
exact bytes** — 64 lowercase hex, same addressing as every other blob
(`docs/BLOB_STORAGE_LAYOUT.md` in the nodalmerge repo).

`RepositorySnapshot.TreeHash` = hash of the **root** tree blob. Snapshots written in this
format carry `TreeFormat: "cas-tree"` and `TreeEntries: null`; legacy snapshots (inline
`TreeEntries`, or neither) are never rewritten (append-only, AP-5) — readers fall back.

The stored encoding is invisible under the hash (decision record 2026-07-12 §5): v1 and
v2 coexist forever under one resolver; a future re-encoding (e.g. MST-style, cf. core
`mst.rs`) would be a new `version`, not a migration.

## Common rules (v1 and v2)

- **Bytes**: UTF-8, no BOM, single line, no whitespace anywhere outside strings, no
  trailing newline.
- **Canonical JSON writer** (hand-rolled — do NOT emit via a general-purpose JSON
  serializer; their escaping is not canonical):
  - Field order exactly as specified below.
  - String escaping, exactly and only: `"` → `\"`, `\` → `\\`, U+0000–U+001F → `\u`
    followed by **4 lowercase hex digits**. Everything else is verbatim UTF-8 (no
    `\n`/`\t` shorthand, no `\/`, no non-ASCII escaping).
- **Readers** may use any JSON parser; only writers are constrained.
- **Entry ordering**: sorted by **byte-wise comparison of the UTF-8 encoding** of the
  key (v1: full path; v2: name segment). Implement an explicit UTF-8 byte comparer —
  UTF-16 ordinal comparison differs for keys containing surrogate pairs (see the
  `v1-utf8-ordering` vector).
- **Paths**: `/` separators only, no leading `/`, no `.` or `..` segments.
- **Empty directories are not representable** — snapshots track files only (git's
  stance). A directory entry exists only if it has ≥ 1 descendant file.
- **File modes / symlinks**: out of scope (`TreeEntries` carries neither today). Any
  future addition is a `version` bump.
- Content type on `PutBlobAsync`: `application/vnd.nodalmerge.tree+json` — a hint only,
  never identity.
- Hash values inside entries are 64 lowercase hex (BLAKE3), stored verbatim.

## v1 — flat tree (slice 1.1)

One blob for the whole snapshot map:

```json
{"nodalmerge":"tree","version":1,"entries":{"<path>":"<64-hex file blob hash>", ...}}
```

`entries` keys are full repo-relative paths, sorted per the ordering rule.

## v2 — directory tree (slice 1.2)

One blob **per directory**, git-tree style. Unchanged subtrees hash identically across
generations and are shared (never re-stored):

```json
{"nodalmerge":"tree","version":2,"entries":[{"n":"<segment>","k":"f","h":"<file blob hash>"},{"n":"<segment>","k":"d","h":"<subtree blob hash>"}, ...]}
```

- `n` — a single path segment (never contains `/`).
- `k` — `"f"` = file (`h` is the file blob hash), `"d"` = directory (`h` is the child
  tree blob hash).
- Entries sorted by `n` per the ordering rule; kind does not participate (a name cannot
  be both file and directory).
- The root blob is the tree object of the repository root. An empty snapshot is a root
  blob with `"entries":[]`.

## Vectors

`tree-format-vectors.v1.json` pins: empty trees (v1/v2), single file, nested
directories, escaping (`"`, `\`, U+0001), non-ASCII UTF-8 byte ordering (U+FF61 vs
U+10000), and a v2 sharing pair (two roots differing in one root-level file must produce
byte-identical `src/` subtree blobs). `CanonicalTreeSerializerVectorTests` asserts the
production serializer byte-matches every vector and that hashes agree. The vectors were
generated by an independent implementation of the rules above.

## Future migration note

Today Studio (.NET) is the only reader/writer of tree objects. When Phase 5's
server-side reachability walk lands (Rust needs to parse trees for GC liveness), this
doc and the vectors migrate to the nodalmerge repo's parity mechanism (`docs/` +
`engine/commands/` + Rust/.NET dual harnesses), exactly like `BLOB_STORAGE_LAYOUT.md`
and `blob-layout-vectors.v1.json`.
